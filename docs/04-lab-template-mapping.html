Your tasks

  1. Map each column to a template tab. Work across the header row and decide which OWP template each column belongs to — Employee / Worker, Position, Management (supervisory) org, or Job / job level.
  2. Find the data problems. Read down the rows and list everything wrong: dead positions, missing links, duplicates, a worker with no position, and the dirty free-text columns.
  3. Mark mandatory-to-fix vs. defer. For each problem, decide whether it must be fixed before load or whether it's hygiene you can clean up later.

📋 Answer Key

Column → template mapping:

  • Employee / Worker tab: Emp ID, Worker Name, Hire Date, Location, Base Pay, Skills; Mgr ID as the manager reference.
  • Position tab: Position ID, Position Title, Job Code, Supervisory Org, Status; the Employee↔Position link ties a worker to a position.
  • Management (supervisory) org: Supervisory Org + Mgr ID drive the org hierarchy.
  • Job / job level: Job Code → foundational, sourced from the Workday job catalog — do not create job levels in OWP.

Mandatory to start: Position ID, the Employee↔Position link, Supervisory Org, Job Code.

The problems in the file:

  • Zombie positions — P40007 (and confirm P70003): unfilled, never filled, no worker or hire date.
  • Missing manager link — E1005 (Tomás Ferreira) has a blank Mgr ID.
  • Duplicate worker — E1003 (Priya Nair) appears twice with conflicting base pay and title.
  • Worker with no position — E1009 (Ben Osei) has no Position ID.
  • Dirty skills — "Financial Planningg" (typo), "fin. planning", "planning" — inconsistent free text.
  • Dirty locations — "LON", "London, UK" vs. "London".
  • Dirty titles — "Sr. AE", "Sr Account Exec" vs. the job-code label.

Must fix before load (the mandatory ones):

  1. Zombie positions P40007 (and confirm P70003) — close / exclude; don't load dead positions.
  2. Missing manager link on E1005 — breaks the supervisory-org rollup; fix in Workday.
  3. Duplicate worker E1003 (two rows) — dedupe and reconcile the conflicting base pay / title.
  4. Employee with no position — Ben Osei (E1009) — OWP plans by position; assign a Position ID or exclude.

Defer (non-mandatory to start):

  • Standardize skills ("Financial Planningg" / "fin. planning" / "planning" → one value) — matching is manual anyway.
  • Fill missing base pay — fake it for dev, load real comp later.
  • Attrition — not in this extract at all; note it's missing but it's OK to defer.
  • Standardize locations ("LON" / "London, UK" → "London") and titles to the job-code label — good hygiene, not a blocker.

Debrief Questions

  1. You separated four must-fix problems from the defer pile. What's the common thread in the must-fix four, and why does dirty skills or a "LON" location not make that list?
  2. The duplicate Priya Nair rows conflict on base pay and title. How would you reconcile them, and who at Northwind do you go to for the tie-breaker?
  3. P40007 is a clear zombie; P70003 is "likely" a zombie. What makes you confident about one and not the other, and how do you confirm before excluding it?
  4. Ben Osei has no Position ID. Walk through the two options — assign a position vs. exclude — and when you'd choose each.
  5. Everything in the defer pile is real dirt you're choosing not to fix yet. How do you keep that debt visible so it actually gets cleaned up later instead of quietly shipping to production?
